估值口径：PCF 逐券法（core/bond_pcf_valuation.py）
  基数 = 富国官网申赎清单「替代金额」÷(数量×10) = 每只成份券全价（含应计利息）
  盘中 = 逐券叠加「本券收益率变动 × 久期」+ 该券自己的每日应计利息
  开关 = nav(D-1) + 票息 + 国开10Y活跃利率债净价涨跌%（仅参考，不参与估值）

🔴 2026-11-14 两处口径修正（用户反馈"昨日估值偏多"）
  ① 应计利息 carry 不再是固定 6.5 厘/日，改为**按成份券反推票面利率**：
       货币网现券接口同时给出「成交净价 P / 到期收益率 y / 待偿期 T」，
       按年付息债券定价式解年票息 C（数值上=票面利率%）：
           C = (P − 100×(1+y)^−T) ÷ ((1 − (1+y)^−T)/y)
           carry_i = C ÷ 365               （元/百元面值/日）
       逐券各计各的息，组合 carry 由篮子结构决定。实测 17 只非零券命中 17 只，
       新券 1.6~1.9%、老券 2.3~2.8%，数量加权 0.005472 元/日
       （旧固定 0.006500，高估约 16%）。行情全缺才回退旧兜底值。
       历史静态估值的 daily_coupon 也从 0.02 元/份/日（≈年化6.1%，明显过大）
       改成 static_carry_unit() 的计算值 ≈0.0064 元/份/日。
  ② 仓位显式分拆：债券 99.52% + 一日逆回购 0.48%
       NAV_basket = (Σ 数量×10×估值全价 + 预估现金) ÷ 最小申赎单位
       NAV_repo   = NAV(D-1) × (1 + r_GC001 × 计息天数/365)
       NAV_est    = 0.9952 × NAV_basket + 0.0048 × NAV_repo
       r_GC001 取腾讯行情 sh204001 字段[3]（年化%），落在 0.3%~5% 才采用，
       否则回退默认 1.5%。取值与来源都记在 detail["仓位"] 里可核对。
  相关可调常量（core/bond_pcf_valuation.py 顶部）：
       BOND_WEIGHT / REPO_WEIGHT / REPO_ANNUAL_DEFAULT / ACC_YEAR_DAYS / DAILY_ACCRUAL

🔴 2026-11-14 估值差归因（11-13 实测：模型 119.2517 vs 实际净值 119.1596，+7.8bp）
  先排除：PCF 篮子恒等式 (Σ替代金额+预估现金)÷最小申赎单位 = 119.49757
          = 11-12 官方净值，偏差 -0.003bp；carry / 99.52-0.48 仓位 / 逆回购
          合计影响都 < 1bp。所以差值不在 carry，也不在仓位。
  两个真实原因：
  ① 日期错位（首要）：PCF(D) 的替代金额对应 **D-1 收盘**；货币网行情 show_time
     是 D 日；而最新官方净值已经是 D 日的 119.1596。旧代码不比日期，把 D 日行情
     再叠到 D-1 篮子上，等于把「11-13 的回溯估值」当成「当前估值」输出。
     → 现在检测「行情日 <= 最新净值日」即把**价格效应归零**（不重复叠加）；
       detail["日期对齐"] 列出四个日期可核对。
       🔴 2026-11-14 东哥定稿：页面数值必须「按计算来」，所以**不再冻结官方净值**、
       也不再做残差拟合。盘后/周末仍按「逐券票息 × 天数 + 逆回购计息」算出 est
       （实测 11-14 周末：官方净值 119.1596 → 模型计算 119.1659，
       method=pcf_basket_carry_only）。开关见文末「纯计算口径」。
  ② 逐券成交 bp 失真：货币网 bp 是逐券成交口径，低流动性老券常整天无成交，
     bp 滞留成 24国开10=0.25、24农发20=0.31，把组合加权 Δy 从基准 3.25bp
     拉到 2.59bp，而按实际净值反推需 3.48bp → 当日少跌 7.86bp。
     → 默认 DY_MODE="curve"：用 10Y国开活跃券 bp 作组合统一基准（曲线平行移动），
       逐券 bp 只留明细；DY_MODE="per_bond" 可切回旧口径做对比。
  ③ 篮子改为「相对变动率 × 最新官方净值」，消掉申赎口径与净值的估值基差。
  ④ 残余 ≈2.87bp 属「成交口径 vs 中债估值口径」结构差：早期版本会盘后把残差写
     入 data/bond_511520/calib.json，EMA 平滑后于下一交易日盘中校准。
     🔴 2026-11-14 起按东哥要求「不需要调整去拟合，根据计算来」：
       CALIB_APPLY=False（估值公式完全不乘校准系数）、CALIB_AUTO=False（不写样本），
       两个开关仅作回溯/实验保留；detail["校准"] 明确写「未启用」。
       残差仍会算出来放在 detail["模型口径偏差"]，但**只作诊断，绝不修正估值**。

⚠️ 数据源可达性（重要，换机器/换网络必看）
  富国官网 www.fullgoal.com.cn 与中国货币网 www.chinamoney.com.cn 在

  🔴 关于"日志报错"（2026-11-13 修）
    早期版本在链路全失败后会**冻结 300 秒**，期间每次刷新都刷同一条 WARNING，
    导致看板日志刷屏、而且网络恢复了还要白等 5 分钟。现在的行为：
      · 退避改为指数增长：5s → 10s → 20s → 40s → 上限 60s，到期**自动**重试全部链路；
      · 日志只在**状态切换**时告警：正常→失败打 1 条 WARNING，之后连续失败降为
        debug；失败→恢复打 1 条「取数链路已恢复」+「官网 PCF 已恢复在线抓取」。
      · 一次断网在 30 秒刷新周期下通常只看到 **1 条** WARNING，不是每屏一条。
    如果你看到 `取数链路全部失败（第 N 次），60 秒后自动重试`，说明本机确实连不上
    数据源（不是程序 bug）：启动代理客户端并开启系统代理，或建 proxy.txt 写代理地址。

  🔴 周末 / 当日 PCF 未发布（2026-11-14 修）
    富国官网在非交易日会返回一个字段全是 "--"、成份券表只有表头的**空模板**。
    旧代码把它当成"页面改版"直接抛异常，整条 511520 估值链会断掉。现在按
    "当日 PCF 尚未发布"回退本地快照，日志与悬浮提示会明确写"非交易日或官网未披露、
    披露后自动切回在线"，与"网络不可达"区分开（排查指引完全不同）。
    降级结果只缓存 60 秒，官网一旦发布能很快切回在线。

2026-11-16（二）：511520 看板估值错误的根因 —— TLS 指纹被拦
==========================================================================

现象（用户报）：跑 start_dashboard.bat 后 511520 估值还是错的。
  手工在终端跑   → est=119.1331  method=pcf_basket_spot  现券命中 15/17
  bat 起的看板   → est=119.1822  method=pcf_basket_est
                    note「现券行情不可得，逐券用活跃券Δy推算」，指数价「失败」

根因：不是代理、不是算法，是 **curl_cffi 的 TLS 指纹在新版 Chrome 上被丢包**。
  bat 里有 `set "HTTP_PROXY="` 主动清空代理（这一步是对的），于是必须直连；
  而直连时 impersonate="chrome" 会用到新版 ClientHello，这条网络链路上的
  设备正好对它丢包 → 货币网 6~10 秒超时 → 现券成交抓不到 → 走 PCF推算兜底。
  实测（连 www.chinamoney.com.cn，无代理，三轮复现一致）：
    chrome / chrome120 / chrome131 / chrome136 / firefox133 → 8~10s 超时
    chrome110 / edge101 / safari / safari17_0              → 0.2~0.4s 正常
  终端里因为继承了 55159 代理，走代理绕过了这个拦截，所以「终端能跑」。

改法（core/bond_pcf_valuation.py）：
  ① 新增 TLS_IMPERSONATE_CANDIDATES = ("chrome110","edge101","safari","chrome","chrome120")
     把已知可用的指纹排在前面；_req() 在每条链路内部按候选表逐个试，
     成功即锁定到 _IMP_OK["fp"]，之后本轮不再试其它指纹。
     只有「连接超时」才换下一个指纹（其它错误换来也一样）。
  ② _get()/_post()/CFETS 估值、上交所 PCF 的 impersonate 默认值改为 None，
     统一交给候选表决定，不再有硬编码 "chrome" 遗漏。
  ③ clear_caches(reset_net=True) 一并重置 _IMP_OK，换网络后能重新挑选。

效果：bat 场景（无代理）首轮探测仅 0.37s，直接锁定 chrome110；
  511520 恢复 method=pcf_basket_spot、现券命中 15/17、指数价 100.14（不再"失败"）。

另外核对过一个「看似 bug」的地方，结论是**不能改**：
  低流动性老券无当日成交时（24农发20/24农发10，合计权重 3.45%），
  走 c) 分支按组合Δy×久期推算。曾尝试改成「活跃券同期净价变动率」代理，
  实测反而更差 —— 活跃10Y券的单券成交价 10 分钟内能从 100.13 跳到 100.55（+0.4%），
  用它代理 3.45% 权重会把 est 抬高 8bp（119.06→119.16）。单券噪声 >> 老券真实价格效应，
  已回退，代码里留了注释说明为什么不要改。

2026-11-16（三）：511520 估值口径最终确认（东哥澄清）
==========================================================================

问：511520 是不是用 PCF 清单估值？没找到成交额的时候怎么算？
答：**是 PCF 清单逐券估值**。逐券三层优先级，落地如下：

  ① 当日有成交净价  → 用 PCF 全价 + 货币网真实成交净价的跨日变动（零 Δy 推算）
  ② 当日无成交额    → 用 **国开10Y活跃利率债** 的 Δy × 该券修正久期（平行移动假设）
  ③ 两者都拿不到    → CFETS 逐券估值全价两日变动 / 曲线Δy

实测（2026-11-16 11:24，bat 同款无代理环境）：
  est = 119.014  method = pcf_basket_pcf_plus_active10y
  note = 16/17 只按 PCF 逐券真实净价，1 只无成交额、用国开10Y活跃利率债Δy×久期推算
  来源构成 = {"净价实际变动": {"只数":16,"权重%":97.41},
              "无成交→国开10Y活跃券Δy": {"只数":1,"权重%":2.59}}
  唯一走兜底的券：240410 24农发10  权重 2.59%  久期 6.65
                  活跃券 26国开10 Δy=+2.45bp → ΔP = -0.148%

为什么这样分：
  · 97.41% 的权重吃的是**真实成交价**，没有任何 Δy 假设，这是最干净的部分；
  · 只有 2.59% 出头的低流动性老券整天不成交，货币网根本不返回，
    这时拿全市场流动性最好的国开10Y活跃券作平行移动基准，是行业标准做法，
    且权重小、误差被摊薄（注入验证：Δy 从 0.9 改到 20.0，est 仅动 -3.4bp，
    与 2.59% 权重的理论影响 -3.3bp 完全吻合，其余 97.41% 一动不动）。

⚠️ 注意区分（本轮踩过的坑）：
  · 「不要国开10Y活跃券参与估值」是**错**的理解 —— 它在无成交时是兜底基准。
  · 「用活跃券的净价变动率代理老券」是**更差**的做法（见上一节末尾），已回退。
  · 活跃券的另一用途仍是展示「指数价/指数涨幅」，不受本口径影响。

同步改动：
  core/bond_pcf_valuation.py  ALGO_NAME = "PCF逐券篮子·成交净价/活跃券Δy·纯计算"

                              detail 新增「估值来源构成」（_src_mix 汇总）

2026-11-16（四）：511520「估值幅度远小于活跃券跌幅」核查 —— 3 个真实 bug
==========================================================================

用户报：「国开10Y活跃利率债都跌了 0.47%，实时估值幅度却远低于这个，请核查。」

核查结论：**先说清楚——那 0.47% 是错的，它当时在涨。** 顺着这条线挖出 3 个
互相叠加的真 bug，修好后方向、幅度、久期全部归位。

────────────────────────────────────────────────────────────
Bug 1（最严重，方向全错）：货币网 `bp` 字段恒为正，符号丢失
────────────────────────────────────────────────────────────
现象：指数涨幅显示 -0.45%~-0.47%，而该券真实净价在涨 +0.21%。

证据（实测 1543 条原始记录）：
  · bp    < 0 的条数 = 0    (0.0%)   ← 一条都没有
  · bpNum < 0 的条数 = 289  (24.5%)
  · 篮内 17 只里有 3 只 bp 为正而 bpNum 为负，正好对应「净价涨、收益率下」：
      25国开10  bp=1.05  bpNum=-1.05   净价 +0.0793%
      24农发10  bp=0.50  bpNum=-0.50   净价 +0.0284%
      16国开05  bp=1.75  bpNum=-1.75   净价 +0.1357%
  · 用 364 只券做方向一致性检验：
      假设 bp 带符号 → 一致率 81%（69 只矛盾）
      假设 bp 是绝对值 → bp≥0 成立率 100%
结论：`bp` 是「变动幅度」，`bpNum` 才是带符号的真实变动。

影响面（不止 511520）：
  fetch_spot_deal() 是公共取数口，511090/511130/511220 也走它。
  旧代码 `dp = -dur × dy` 里 dy 恒为正 ⇒ **价格效应恒为跌**，
  所以这三只的「指数涨幅」平时也一直显示负数，属同源问题，本次一并修好。

改法：
  core/bond_pcf_valuation.py / fetch_spot_deal()
    dy_bp  ← bpNum（带符号）；bpNum 缺失时才退回 bp（并保留 bp_abs 字段留档）
  修复后 dy_bp<0 的券占 25.1%，与 bpNum 真实分布一致。

────────────────────────────────────────────────────────────
Bug 2：`estimate_duration` 缓存被 scale 污染
────────────────────────────────────────────────────────────
原实现以 `code` 单键缓存结果，但同一只券会被不同 scale 调用：
  组合久期 → estimate_duration(code)        scale=0.9
  活跃券/单券 → estimate_duration(code, 1.0) scale=1.0
先调 0.9 再调 1.0，就把 1.0 的值写回缓存，此后所有默认调用都拿到被放大的久期。

实测（260210 26国开10）：
  0.9 → 9.00；插入一次 1.0 → 10.00；随后默认调用 → **10.00**（应 9.00）
组合久期因此被高估：7.99 vs 真实 7.55（+5.8%）。

改法：缓存键改为 (code, scale)。修复后 0.9 稳定返回 9.00。

────────────────────────────────────────────────────────────
Bug 3：「Δy × 久期」路径全线使用估算久期，未用 CFETS 真实修正久期
────────────────────────────────────────────────────────────
原 `pick_active_cdb10y` 用 estimate_duration(code, scale=1.0)，
对 26国开10 给 10.00，而 CFETS 官方修正久期是 8.76 → 跌幅被放大 14%：
  -0.45%（估算） vs -0.40%（真实）

改法：
  ① 新增 `_real_duration(code)` / `_real_duration_map(codes)`，
     优先取 CFETS 估值文件的真实修正久期（日级缓存，不会额外请求）；
  ② 活跃券、组合久期、静态估值三处全部改为「真实久期优先，取不到才估算」；
  ③ 活跃券返回值新增 dur / dur_src 字段，便于核对。

效果：活跃券指数涨幅 -0.45% → 与真实净价变动只差 0.2bp；
      组合久期 7.99 → 7.55（命中 17/17）。

────────────────────────────────────────────────────────────
修好后为什么估值幅度仍然小于活跃券？—— 这是正常的，不是 bug
────────────────────────────────────────────────────────────
量化答案（2026-11-16 盘中实测）：
  · 活跃券 26国开10 真实 Δy = -0.25bp（在 17 只里排第 13 大，属变动小的）
  · 篮子逐券 Δy：均值 +0.89bp，中位数 +0.75bp，标准差 1.99bp
                 最小 -2.60 ~ 最大 +5.36，极差 7.96bp
  · 权重加权 Δy = +0.74bp
  · 按活跃券 Δy 平行移动推算的篮子价格效应 = +0.0189%
    实际逐券净价效应                        = -0.0531%
    两者差 = 7.19bp

三个结构性原因（都不会随修 bug 消失）：
  ① 组合久期 7.55 < 活跃券久期 8.76，同样的 Δy 折算到净值就小 14%；
  ② 篮内个券离散度极大（极差 7.96bp），单券 Δy 不代表篮子；活跃券本身
     就排在第 13 位，用它做基准必然高估跌幅；
  ③ 新券 vs 老券走势分化：新券(26年) Δy 均值 -1.62bp（涨），
     老券 14 只 Δy 均值 +1.42bp（跌），两边互相抵消。

所以「指数涨幅」列只作方向参考，估值一律以逐券真实成交净价为准。

二、关键设计：为什么用 val_method='pending' 而不是 'bond'
────────────────────────────────────────────────────────────
如果直接给 'bond'，会掉进 estimate_bond_nav 的未知分支返回 est=None，
上层 `est = _b["est"] if _b["est"] is not None else _nav` 会**静默回退成
最新官方净值** —— 那就等于把「昨天的净值」冒充「今天的实时估值」，
比留空更糟（溢价会算成 0，看着像没事，实际是假数据）。

所以新增独立状态位：
  fund_profile.val_method = 'pending'
  含义 = 已收录、实时/历史估值算法未接入

三处配套处理：
  1) core/etf_iopv_quote.py  LOF 分支新增 `if vm == "pending"` 显式分支
     → est=None、err=「实时估值待接入（已收录，估值算法后续补充）」、
       bond_method='pending'，不会落入 `nav×(1+0.95×指数涨幅)` 的凑数逻辑。
  2) core/bond_etf_valuation.py  estimate_bond_nav 的未知分支
     → 新增 _PENDING_VAL_CODES 判，method 由 'unknown' 改 'pending'，
       note 由「未知债券基金」改「实时估值待接入」，免得看着像代码写错。
  3) core/fund_history.py  get_history / _cash_algo
     → 返回 rows=[]、algo.id='pending'，不落 LOF 的「净值×指数涨幅」
       也不落 bond_legacy 的「日均增长法」（那是货币型的算法，张冠李戴）。
  4) frontend/index.html  bondStaticTip
     → bond_method=='pending' 时给专属 tooltip，说明接入方式。

一、为什么不能沿用任何一种现成的逐券算法（六条路全部实测排除）
────────────────────────────────────────────────────────────
关键事实：这 9 只的成份券全是**交易所**信用债（115xxx / 240xxx / 137xxx），
与银行间信用债是两套完全不同的市场，现有三套算法一个都用不上。

  路径① 交易所实时行情
        → 新浪 / 东财 push2 / 上交所固收，全部返回 0.000。
          115323 近一年仅 4 个交易日有成交记录，行情源根本不推送。
          ⇒ 无价可用。

  路径② CFETS 逐券估值（现有 fetch_cfets_valuation）
        → 全表仅 252 条，只覆盖政金债 / 国债。
          对 313 只成份券命中率 0.0%。⇒ 完全无交集。

  路径③ 货币网银行间现券（现有 fetch_spot_deal）
        → 那是银行间市场。名称含「公司债 / 科创债 / AAA」命中数 0。
          MTN 虽有 51 条，但 Δy 中位 +7bp（上行），而当日 9 只 ETF 全涨
          0.3~0.67% —— **方向完全相反**，拿它代理等于符号错了。

  路径④ 银行间信用债曲线代理
        → 同上，市场错配。

  路径⑤ 兄弟 ETF 价格绝对数代理
        → 回测 |误差| 中位 3.4~5.2bp、P90 25~36bp、max 88bp。
          根因：折溢价日间波动剧烈（实测单日折价可达 -0.77%），
          用价格当净值是拿噪音当信号。⇒ 精度不够。

  路径⑥ 政金债 Δy × 久期 单因子回归
        → 回归出「隐含久期 12.81 年」——物理不可能（这批 ETF 持 2~3 年券）。
          根因：短久期 AAA 信用债的日波动不只来自利率，还有**信用利差走阔**，
          被误当成久期放大。⇒ 单因子模型结构性错误，不是参数问题。

坑 1 · carry 不能叠加（本轮第 4 个 bug，方向性错误）
  中证债券指数是**财富指数**口径，日涨跌里已含当日票息；ETF 二级价格
  同样随净值上行、涨幅也含票息。再叠一次 carry 就是重复计息。
  19 个交易日实测（vs 累计净值涨跌）：

  ⇒ ①②③ 三条主口径一律不叠 carry；carry 只留给④「无任何方向信号」兜底。

坑 2 · 分红除权
  551500 于 2026-11-16 每 10 份派 16 元：单位净值 102.6844→100.9703
  （-1.669%），累计净值仅 -0.107%。
  511110 于 2026-10-22 每 10 份派 21 元（-2.002% vs 累计 +0.019%）。
  ⇒ 涨跌一律用 LJJZ（累计净值）算，DWJZ 只用于展示。
  历史页进一步：acc×100 − nav = 累计每份分红，当日增量即本日派现，
  对 nav_chg、static_val、price_chg 全部按除息口径复算。
  （acc 在库里只有 4 位小数，×100 后精度 0.01 元，故设 0.05 元门槛滤噪）

坑 3 · 兄弟反推的两个连坐 bug
  Bug A（绝对数中位数）：最初取「兄弟隐含净值的**绝对数**中位数」。
    但各 ETF 净值水平不同（511070 在 103.12、551900 在 102.10、

    ⇒ 必须取**涨跌幅**中位数，再乘本只自己的锚点。
  Bug B（分红日假涨幅）：551500 锚点已是除息后 100.9703，拿兄弟的
    102.x 去比会算出 +1.67% 假涨幅。⇒ Bug A 的修法同时解决此问题。
  坑 3b · 除权日守卫：分红当天本只价格跌幅天然比兄弟大 50bp 以上，
    若照用兄弟中位数会把派现当净值下跌。故当本只自身涨幅与兄弟中位数
    相差 >60bp 时改用本只价格涨幅（阈值 60bp：最低派现率也在 50bp 以上，
    而深市流动性噪音实测可达 27bp，35bp 会误触发）。

一、结论先说：走「转债指数 × 滚动 beta」，不走逐券
────────────────────────────────────────────────────────────
可转债与信用债 ETF 的根本差异：可转债在交易所**有连续竞价成交**（不是像
交易所信用债那样行情恒为 0.000）。实测 11-17 盘中：
  110084 贵燃转债 326,040 手 / 3,794 万元
  110085 通22转债 3,868,580 手 / 3.97 亿元
所以第一反应是「那就逐券算篮子，最准」。实测**否掉**了这条路。

────────────────────────────────────────────────────────────
二、三条路逐一实测（这是本次最重要的证据表）
────────────────────────────────────────────────────────────
① 逐券篮子（交易所 PCF 数量 × 真实收盘价加权）
   实测 2026-11-13 → 11-16 篮子涨跌 vs 实际净值：
     511380  逐券 -3.239%  vs 实际 -3.048%   差 -19.1bp
     511180  逐券 -2.923%  vs 实际 -2.662%   差 -26.2bp
   根因：交易所 PCF 只给「数量」不给「替代金额」。用 Σ(qty×px)/navpercu
   反推比例，两只分别是 10.414 / 10.781 —— **不是常数**，说明 qty 与真实
   权重之间没有稳定换算关系（现金替代、零股处理、成分调整期都会破坏它）。
   ⇒ 逐券不可用。

② 裸指数（beta=1），79 个交易日回测（2026-07-20 ~ 11-16）
     代码      指数                              beta      r        残差中位
     511380   931078 中证可转债及可交换债券      0.9948   0.9997    0.9bp
     511380   000139 上证可转换债券              1.0281   0.9950    5.1bp
     511180   931078 中证可转债及可交换债券      0.7819   0.9827    8.8bp

六、四个坑（都踩过）
────────────────────────────────────────────────────────────
1) 中证 perf 接口单次上限 **45 自然日** ⇒ 约 30 个交易日，不够滚动 beta
   的 40 个样本。解法：csi_series_long() 分段连续请求拼长历史
   （间隔 1.2s 避开 WAF），实测 4 段可拿 121 个交易日。
2) 东财 lsjz 单页上限有限：_nav_series(code, days=300) 直接 IndexError。
   解法：fetch_nav_long() 自己分页累加。
3) 不能拿全样本 beta 回算全历史 —— 那是**前视偏差**，会把 511180 早期
   误差做小而失真。历史页对每个日期只用「该日之前」的样本回归。
4) 可转债**没有票息 carry 项** —— 利息已含在转债全价里。
   这点与信用债 ETF 一致（信用债那边也已删掉 carry），但原因不同：
   信用债是「财富指数口径重复计息」，可转债是「压根没有独立 carry」。

  涨跌幅替代无成交债券的价格？是否有更好策略？

【结论：期货方案实测更差，不采用；当前现券方案已近最优，另修了一个冻结隐患】

1) 期货方案被量化否定（以 CFETS 逐券真实全价变动为真值，14 日回测）
   组合统一Δy 信号的误差（bp，越小越好）：
     · A 国开10Y活跃现券Δy（当前口径）  中位 1.13  最大 3.64
     · B 国债期货涨跌%→等效Δy            中位 3.17  最大 32.96  ← 明显更差
     · C 篮子内含券Δy中位数               中位 0.76  最大 2.33
   期货致命缺陷：标的错配。10Y国债期货跟踪「国债」，511520 持仓是「政金债」
   （国开/农发/进出），存在国开-国债利差 + 换月跳变。实测 11-11→12：
   期货 +0.073% 而政金债真值 -0.258%，方向完全相反，单日误差 33bp。
   且 A 与 C 平均只差 0.06bp、标准差 0.32bp —— 两者本质一致，
   活跃券现券基准已足够好，无需为其引入期货的新风险。

2) 盘中覆盖度实测：货币网现券当日 4248 条，PCF 17/17 只成份券全部命中，
   且每只 dy_bp 都有值（行情时间 13:39~18:55）。「整只券无成交」在盘中
   极少发生；即便发生，代码已有兜底（Δy×久期），不是主要误差源。

3) 真实隐患已修复（core/bond_pcf_valuation.py）：
   活跃券 dy_bp 盘中可能暂时无成交而滞留成 0 → 整个篮子盘中估值被钉死。
   · portfolio_dy_bp()：新增「活跃券 |dy|<0.05bp 且篮子中位 |dy|>=0.5bp」
     的保守判据，冻结时自动切到篮子 Δy 中位数作组合基准。
   · 无成交券兜底分支：改用已稳健处理的 combo_dy，不再直接取可能停滞的
     活跃券 dy_bp。
   三场景验证：正常行情用活跃券(-0.35bp)不变；活跃券冻结自动切中位(-1.0bp)；
   市场平静(全≈0)不误切换；完整估值回归 est=119.5511 不变。
